# 纯侧移与柜体净空修正

2026-11-02，用户指出“向左移动却先转车身、左手扫到动力柜”。此前±55°临时行驶朝向策略已经撤销，不能继续将它解释为纯侧移。

后续用户明确选择“胸部正面垂直朝向柜门／面板”。资产走位现有单独的安全对正阶段，实际对正后再固定朝向平移；手动左右按钮仍不主动转身。本文原“请求开始yaw一直保持”只适用于手动横移或已对正后的平移，不能据此跳过资产朝向门控。最新实测首次机构动作时胸部误差约0.78°，位置和停稳也通过，平移段wz仍全部为0。

## 当前运动流程

先检查双手与柜壳净空，必要时沿验证过的路径收纳双臂；已收纳则跳过。底盘真实停稳后，四舵同步对齐到横向滚动平面并稳定，再从零斜坡加速。机器人左移对应`vx=0, vy>0, wz=0`；右移反向，车身不主动转向。两轮可取+90°、另两轮-90°的等价舵角，并通过滚轮转向补偿，四轮地面运动方向相同，不能只比较关节符号。

导航固定请求开始时的车身朝向，把目标位置分解成底盘X/Y直角路线；每腿只发一个平移分量。所有临时yaw、β越界自动转身和终点强制回旧示教角度的逻辑均删除。航向漂移超过参考2°、横滚/俯仰超过1°或环境间隙不足时停轮取消，不暗中旋转车身补偿。

新增“机器人左移约10厘米 / 机器人右移约10厘米”供现场检查，以机器人坐标为准。它们不触发任何资产操作、不用前后补偿冒充纯横移；当前仿真参考验收为沿轴5mm、侧偏10mm，并记录实际误差。此为演示步长，未按实物标定，不能宣称精密定位。原5mm欧氏误差试验有一次未通过，记录保留。

## 起步冲击处理

旧逻辑在停轮对舵时，上层请求已累积到0.25m/s，放行瞬间会直接跳速。现在底盘内部也执行放行后的0.15m/s²参考斜坡：实际停车0.1s → 同步限速对舵 → 实际角度/轮/根位置稳定0.1s → 从零起步。舵角组在变速、反向时保持，不在±90°边界反复换解。力矩上限、摩擦、驱动增益保持原值，没有固定或瞬移基座。

`park_base()`为显式四轮回正驻车，整个过程轮速目标0。只有确实需要动态收臂时才先驻车，已处运输姿态不重复执行。准备阶段同样监测姿态，不能把收臂反作用误当侧移。旧准备过程大偏航的原因未单独隔离，不能仅凭旧切线轮姿断言因果；当前冷启动直接使用已验证运输初态，动态准备超阈值会停止。

## 左手碰柜的覆盖缺口

主柜壳`/World/Cabinet/CabinetBody/CabinetBody`原来没有CollisionAPI，31个可视Mesh中只有11个碰撞体。现在在SessionLayer增加静态三角网格碰撞，数值contactOffset为1mm、restOffset为0，未写回源资产。四条物理射线已实际命中主柜壳，50DOF和雅可比仍有限。

旧导航还通过可见性相关BBox读隐藏碰撞体，恰好漏掉23个Cube和4个Cylinder，只检查69个Mesh。现改解析几何、忽略可见性并强制覆盖审计，当前96/96全部纳入。四个舵轮另有真实几何扫掠包络。

左臂原六关节近零是伸展姿态，不是安全运输位。新收臂路径由当前六轴FK/IK和新鲜场景几何验证：1071个配置、最大表面步长2mm，环境间隙至少0.3737m、非相邻身体间隙至少9.8mm；手部水平伸出从1.2336m降到0.4074m。新场景初始化采用`verified_transport_pose.json`，并校验源URDF与USD哈希，防止新机器人套用旧角度。

移动期间以真实PhysX位姿持续查询左右手/臂与环境的距离，不只平移冻结的初始手姿态；还保留柜壳可视凸包，避免完全穿进闭壳后仅按三角表面距离误判安全。参考最小净空5cm。身体自碰撞求解器仍按用户要求暂缓。
