## 3. 怎么驱动仿真服务

单进程 Isaac + FastAPI，`127.0.0.1:18765`（`ROUTE_MANAGER_PORT` 可覆盖）。

```
GET  /health                     -> {"status":"IDLE|PENDING|RUNNING|SUCCESS|FAILED","task":...}
POST /execute {"action":..., "parameters":{...}}
POST /python  {"code":"...executor.xxx()..."}     # 在仿真主线程 exec，executor 在作用域里
```

- **action 是反射派发**：`RobotManager` 的任何公开方法都是 action。没有 `get_link_poses`，
  要读任意 link 位姿只能走 `/python`。
- **单任务槽**：并发请求直接 **409**。写客户端必须容忍 409 并退避重试；**绝不能同时开两个
  轮询者**。调试前先 `./scripts/start_ros2_contract.sh stop`，否则它的定时轮询会把队列占满。
- `/python` 的返回值**不回传**，要让仿真端把结果写到 `/tmp/*.json` 再本地读。
- 常用 action：`load_scene`、`load_robot`、`move_j{side,positions,duration}`、
  `set_gripper_position{side,position}`（睿尔曼语义 1–1000，1000=全开）、
  `get_sim_state{ref_link}`、`send_joint_command`、`set_base_velocity`。
- **重启顺序**（`scripts/bringup.sh --no-vr` 已封装）：停中继 → 起服务 → `load_scene` →
  `load_robot` → **抬臂（必须在建相机之前，相机 prim 会让物理视图永久失效）** →
  Jacobian 标定 → 相机 → 最后才起 ROS2 中继。

### `get_sim_state` 的朝向约定

`sides.{left,right}.flange|tcp.orientation` 是 **`[w,x,y,z]`**。

## 4. 今天的关键发现（按踩坑代价排序）

### 4.1 `get_link_transforms()` 的四元数是 `xyzw`，不是 `wxyz` —— 已修，未提交

`robot_manager.py` 的 `_link_pose_table()` 把 TensorAPI 的 `pos(3)+quat(4)` 当成 wxyz 读。
**位置不受影响，朝向整体错掉**——表现是"锚点位置永远对得上，一动关节就差 90°"。

判据（决定性）：同一批位形按 `xyzw` 解出的基座常量变换在样本间只差 **0.1°**，按 `wxyz`
解差 **55.8°**。`isaac_teleop.py:1053` 早就有 `x, y, z, w = q  # xyzw` 的正确写法。

改动（工作区，未提交）：
- `robot_manager.py` `_link_pose_table()`：读入后重排 `[[3,0,1,2]]`，入库统一 wxyz
- `robot_manager.py` 相机偏移那处：`x, y, z, w = quaternion`
- `scripts/scene/register_cameras.py:136`：`_q2Rm([v[6], v[3], v[4], v[5]])`

**副作用**：`scripts/scene/cam_follow_offsets.json` 被清成了 `{}`（旧偏移是用错的旋转算的）。
需要重跑 `register_cameras.py` 才能恢复相机跟随偏移。

### 4.2 "锚点残差 0.00mm" 是恒等式，不是验证

锚点法用 `R_ab = R_f @ R_fk(q)ᵀ`、`t_ab = p_f - R_ab @ t_fk` 反推基座位姿，再算
`ee_world(q)` —— 残差**恒等于 0**，任何链都成立。它证明不了模型对不对。
真正的验证只能靠**改变 q 之后**预测位移是否还对得上（`anchor_scan.py` 干的就是这个）。

### 4.3 `solve_ik` 的雅可比切片错误 —— `valve_turn.py` 已修，`valve_trajectory.py` 仍是坏的

`arm_kin.jacobian()` 返回 **`(n, 6)`，每行是一个关节**的 `[vx vy vz wx wy wz]`。
写成 `Jf[:3, :]` / `Jf[3:, :]` 取的是**前三个关节**，不是位置/旋转块：

```python
Jf = arm_kin.jacobian(chain, q, R_ab, t_ab)     # (n,6)
Jt = Jf.T                                       # (6,n)  ← 必须先转置
J  = np.vstack([Jt[:3, :], w_rot * Jt[3:, :]])
```

症状：从"手臂自然下垂"解到"法兰 +Z 朝下"这种接近 180° 的姿态差时，所有滚转都残差
500–800mm。**`scripts/valve_trajectory.py:140` 还带着这个 bug，别用它。**

### 4.4 手轮 bbox 读到 109mm 是被污染的，真值 80mm

`/World/vla_table/valve_asset/valve_1/wheel_link` 的 bbox 给出 109.2mm，因为它的子 prim
`wheel_joint` 有无效 bound（`±3.4e38`），污染了父级。**从 mesh 顶点量**才是真的：

| 量 | 值 |
|---|---|
| 手轮盘直径 | **80.0 mm** |
| 盘高 | 32.3 mm |
| 中心（世界） | `(0.750, 0.000, 7.0691)` |
| 轴 | 世界 **Z**（无限制，可连续转） |
| 初始 yaw | 90° |

夹爪全开两指垫间距 **88.35mm** → 能夹住，**单边余量约 4mm**。这是整个任务能成立的边界。

### 4.5 抓取点（TCP）随夹爪开合移动

抓取点 = 两指垫中点，在法兰系下的偏移**不是常量**（四连杆）：

| 夹爪状态 | 沿法兰 +Z 的偏移 |
|---|---|
| 闭合（position 7） | 0.2572 m |
| 全开（position 1000） | 0.2461 m |

**不要写常量**。`get_sim_state` 同时返回 `flange` 和 `tcp`，每次现算 `R_flangeᵀ @ (p_tcp - p_flange)`。

### 4.6 PhysX 的雅可比是绕连杆质心的，不是 TCP

`arm_kin.py` 的 docstring 记录了这一点：角速度行一致，线速度行差 `ω×(p_tcp − p_com)`。
所以**不要用 Isaac Lab 的 `DifferentialIKController`**，用 `arm_kin` 的数值雅可比。

### 4.7 机械臂的 home 位形就是极限伸长

`bringup.sh` 抬臂后法兰在 `(0.055, -0.951, 7.766)`，距臂座 **0.891m = 臂展上限**。
所以从 home 直接解目标位姿很容易卡住，`solve_ik` **必须多起点**。
