# 人形机器人阀门手轮操作

当前对象是整机上的 RM65 六轴右臂、CTAG2F120 夹爪及原 80mm 手轮资产。
实现采用独立臂座 FK、真实轮轴圆弧、接触后实测 TCP 重规划、被动手轮实际转角反馈。
不是给手轮加电机，也没有把手轮固定到夹爪。

## 模块与执行边界

- `scripts/valve_feedback.py`：从现有 PhysX 刚体读取机器人、轮轴、固定链、双指垫接触；不创建探针相机。
- `scripts/valve_plan.py`：纯 NumPy/SciPy/XML 规划；支持假设底盘平移和升降、真实轴及开合 TCP 模型。
- `scripts/valve_transit.py`：单右臂接近绕行；确定性弯折候选和 RRT-Connect，搜索后必须完整细扫掠。
- `scripts/valve_safety.py`：当前全身/环境精确几何、96形状覆盖、2mm表面步幅及0.01rad关节步幅的自适应扫掠。
- `scripts/valve_runtime.py`：只在已有仿真主线程中工作，通过 `executor.step()` 推进反馈状态机。
- `scripts/valve_grip_stability.py`：连续承载与实测机械运动停稳窗口，完整保留SDK原始速度。
- `scripts/physics_view_guard.py`：旧Tensor/World失效后暂停并阻止重复读取。
- `scripts/valve_operation.py`：HTTP客户端与离线规划入口；处理409，真实失败返回非零退出码。
- `scripts/valve_station.py`：在现有场景添加独立可移除的验证工位，不重载机器人或改源USD。

旧 `valve_turn.py` 的端点序列只保留 dry-run 对照，不再允许绕过新流程执行。
旧 `valve_trajectory.py` 仍是法兰参考序列，不是本手轮的执行入口。

当前运行时只执行**已在可达工位停稳**的机器人。非零 `--body-xy` 或 `--lift-delta`
可以离线规划，但实际 `run` 会明确返回 `requires_placement` 并拒绝下发；它尚未自动接入
底盘导航/升降控制，不能把假设臂座当成已经走到位。

## 使用

所有命令从仓库根运行。现场端使用 Isaac Sim 6.2 服务 `http://127.0.0.1:18765`；
先检查服务实际存在，不能据本文推断当前已启动。
同一服务只允许一个控制者；运行期间不要让其他聊天或UI同时下发动作。

```bash
# 若现场没有阀门，只在确认布局后添加仿真验证支架；位置须按现场规划，不通用。
python3 scripts/valve_operation.py setup --position X Y Z

# 只读当前物理反馈
python3 scripts/valve_operation.py capture

# 完全离线，不访问服务；可加入 --body-xy DX DY / --lift-delta DZ 做假设摆位
env -u DISPLAY -u PYTHONPATH -u LD_LIBRARY_PATH \
  /home/jy/micromamba/envs/isaacsim6.0/bin/python scripts/valve_operation.py plan \
  --snapshot outputs/valve_operation_20261102/snapshot.json

# 现场只读避碰预检；默认严格检查全部自身碰撞
python3 scripts/valve_operation.py preflight

# 本机资产存在底座与四轮的既有装配重叠，只有显式不变证明才允许单右臂任务。
python3 scripts/valve_operation.py preflight --audit-static-assembly

# 必须预检/停稳/反馈全部通过才下发；仍会重新采样和预检。
python3 scripts/valve_operation.py run --audit-static-assembly --angle 90

# 单任务HTTP正在执行时，以下两项只读写本地文件，仍能使用。
python3 scripts/valve_operation.py status
python3 scripts/valve_operation.py stop
```

可用 `--output DIR` 为每次验证单独保存证据，`--valve-root` 指定其他阀门根路径。
`--roll` 选择抓取滚转；`--grasp-axial-offset` 是 TCP 沿真实轴相对网格中心的目标偏移(m)，
不会更改实测手轮中心。停止文件 `DIR/STOP` 存在时程序拒绝自行重启，应由新的明确运行请求
在确认停稳后移除它；不能用删除文件强行继续失败中的动作。

## 门控与证据

流程为：初始稳定窗口 → 渐开夹爪 → 避碰绕行接近 → 下降 → 渐进夹持 →
读取双指垫接触与实测TCP → 重规划完整轮轴圆弧 → 连续流送 → 核对轮轴实际方向/幅值/滑移 →
松爪 → 用最新TCP规划退出。各阶段严格等实际关节位置、速度和TCP到位，超时拒绝放行。

源手轮没有 DriveAPI；阀体固定证明必须通过启用的 FixedJoint 连到世界或明确的运动学夹具。
运行时监测底盘、固定夹具、轮轴约束和控制者竞争。失败/STOP时停轮，仅给右臂和夹爪主动
关节写有限的实测保持值，不把全身反馈回灌成目标。

参考环境净空为5mm、自身主要运动部位8mm。只有两片指垫允许对手轮进行不超过1mm的接触
穿深；两片支撑指垫的 `right_gripper_*_in_link` 对手轮要求1mm**正间隙**，不允许接触穿模。
这一工具缓冲来自本次几何布局需求，不是硬件标定值。其他部位不采用这个覆盖规则。

底盘资产的24个原始形状重叠涉及底座与四个轮体。`--audit-static-assembly` 不修改USD、
碰撞开关或过滤对，而是记录全部原始重叠并证明受控右臂/夹爪关节不会改变它们。每个样本
继续检查96形状；若轮舵角、装配相对变换、穿深或形状对发生超限变化即拒绝。此模式的
`globally_collision_free` 明确为 `false`，只可能给出 `pass_for_requested_motion=true`。

输出包含 `snapshot.json`、`plan.json`、`preflight.json`、`progress.json`、`trace.json`、
接触后重规划轨迹和 `result.json`。只有最后的实际轮轴角满足方向和幅值要求、接触/滑移及
退出均通过，才返回 `success=true`。预览成功或机械臂动过都不算阀门操作成功。

夹爪各阶段另外保存`*_grip_diagnostics.json`：逐物理步的原生leader q/v、原生位置目标、
最后已下发夹爪指令、双侧法向冲量，以及both/stopped/dwell决策和退出原因。内存采集后
在阶段结束或失败时落盘，不增加控制下发，不改变门槛。此日志是第三轮失败后的代码补充，
尚未重新进行物理试验，不能据此补造第三轮缺失的连续载荷/关节历史。

当前所有控制阈值、支架尺寸及摩擦参考值均明确记录为仿真参考，不代表真机规格。
