RouteManager（/home/jy/RouteManager，github.com/9527here/RouteManager）：Isaac Sim 人形仿真 HTTP 管理服务器，双线程任务队列 + action 反射分发。

- **端口 18765**（2026-09-23 从 8765 改掉防冲突，全仓库统一；可用 `ROUTE_MANAGER_PORT` 环境变量覆盖，load_scene.sh 同名变量生效）。Isaac 热缓存时冷启动仅 ~8s；日志里 uvicorn 的 INFO 行会被 Kit 以 `[Error] [py stderr]` 前缀转发，是外观噪音非真错误。

- **用户环境**：micromamba env `isaacsim5.1` 是本项目用的环境（机器上另有 isaacsim6.0，用户确认 5.1 才是本项目的；2026-09-23 用户原话确认）。run.sh 已写死自动探测 isaacsim5.1，可用 ISAAC_PYTHON 覆盖。
- **默认机器人**（2026-09-23 用户指定）：`humanoid_upper_body_v3_ctag2f120`，USD 资产包在 `/home/jy/datasets/vla_data/L1_制作资产/载体设备/humanbody_urdf/humanoid_upper_body_v3/urdf/humanoid_upper_body_v3_ctag2f120/`（顶层 .usd + configuration/ 四层：base 291MB/physics/robot/sensor，defaultPrim=humanoid_upper_body_v3，带 IsaacRobotAPI）。**同目录的原始 URDF 用 package:// 引 mesh（142 处），Isaac 导入器不解析**，故为此新增 `load_robot` action（USD 直接挂载+注册 Articulation，自动向下找 ArticulationRootAPI）。config.json 的 robot 节是**多机器人预设库**：`robot.name` 定默认 + `robot.presets` 按名切换 + 请求传 usd_path 临时指定；**预设条目支持 usd_path 或 urdf_path**（URDF 走 load_urdf 自动转换，须绝对路径 mesh）。现有预设：`humanoid_upper_body_v3_ctag2f120`（USD）+ `v3_ctag2f120_cameras`（7 路相机版 URDF，在 ~/下载/humanoid_upper_body_v3_ctag2f120_min/，见 [[gripper-swap-task]]）。一键加载脚本 `scripts/load_scene.sh`（-n 预设名 / -a 资产路径 / --no-ground / --health，内置等服务与关节摘要）。**2026-09-23 实测教训：pxr 的 UsdPrim 没有 GetDescendants()，遍历后代用 GetAllChildren()**（首次 load_robot 因此失败，已修）；用户服务日志里的 `node_STL_BINARY_` 警告是渲染端良性噪音。数据集里另有 `人形上装部分-URDF` USD 包但是空壳（base 层仅 5.7KB 无 mesh），没入预设；cthm3f460 的 USD 尚不存在。
- **2026-09-23 修复轮**（审查发现 7 项全修）：ROS2 闭环重构（外部节点发 command_topic → 主线程施加 articulation；仿真按 publish_rate 发 state_topic，同节点订阅回读作 feedback）；send_joint_command 改非阻塞插值状态机（RobotManager.step 逐帧推进），且 HTTP 直连路径**不回发** command_topic（避免回声）；load_urdf 的 fix_base 签名默认改 False 与 config.json 对齐、加载后自动 world.reset()+articulation.initialize()；DEFAULT_LOADING_TASKS 换掉模板遗留名（load_car/load_grid_map），main.py 显式传 {load_scene, load_urdf, load_robot, add_camera}；add_camera 新增 attach_to 挂载随动（prim_path 必须在 attach_to 之下）；sim_env 的 ros2.bridge 插件启用加 try/except 降级；地平面改带视觉的 GroundPlane（失败退纯碰撞）。
- **验证边界（2026-09-23 更新）**：Isaac 实机链路**已打通**——相机版机器人 USD 加载成功（50 关节，prim_path=/humanoid），get/set_joint_positions 读写回环验证通过（left_arm_1_joint 0.1rad 精确读回）；**7 路相机已挂载实机并出图验证**（head_zed_x 前视 + head_surround_rear 后视看到躯干，attach_to 随动生效，无过曝）。挂载配方：attach_to={cam}_link、局部 position=[0,0,0]、rotation_euler=[90,0,-90]、intrinsics={fx,cx,cy}（ZED 组 672.20/960/600 @1920×1200，335L 组 640/640/400 @1280×800）+ DomeLight /World/sky_light intensity 600（3000 过曝）。**注意 link 名是 gemini_335l 不是 335lg**。踩坑：add_camera 默认 name 取 prim_path 末段，多相机都叫 camera 会撞场景注册表重名（已改为全路径派生，热修复用显式 name 绕过）；/python 端点多行代码经 JSON 传易炸转义，用 python urllib 驱动脚本稳。相机 ROS2 图流（ROS2CameraHelper）未接，RouteManager 目前是 HTTP 抓图模式。热修复配方（不丢场景）：`/python` 里 `importlib.reload(robot_manager); executor.__class__ = robot_manager.RobotManager`。
- **Isaac Sim 5.1 API 兼容教训（2026-09-23 实测）**，robot_manager.py 已全部适配：①`isaacsim.core.prims.Articulation` 构造第一参改名 `prim_paths_expr`（view 风格）——用**位置传参**兼容新旧；②`isaacsim.sensors.camera.Camera` 构造不再收 focal_length/clipping_range，用 `set_focal_length(米)`/`set_clipping_range(near,far)` setter——**isaac_add_cameras.py（现放 RouteManager 根目录）旧版把 mm 数传给了米制 setter，焦距差 1000 倍（110°变 0.16°），已修**；③`set_local_pose` 参数名是 `translation`（不是 position），且 `set_world_pose`/`set_local_pose` 多了 `camera_axes` 参数（"world"=Z上X前 / "usd"=原始USD约定即[0,0,0]朝-Z，项目用 "usd"）；④view API 关节位置向量形状 (M,K)，单机器人 M=1，读写都要 reshape；`initialize()`/`dof_names`/`get_dof_index`/`set_joint_positions(positions, joint_indices=)` 均兼容。查 API 签名不用起 Kit：直接 grep `site-packages/isaacsim/exts/isaacsim.*.*/impl/*.py`。
- **相机内参体系（2026-09-23，两份脚本分叉已理清）**：`isaac_add_cameras.py` 存在两份——原版在 `~/下载/humanoid_upper_body_v3_ctag2f120_min/humanoid_upper_body_v3/scripts/`（用户实际在用），RouteManager 根目录是旧拷贝。原版本就有 `--intrinsics`（**纯打印** pinhole_k：hfov→OpenCV K，fx=(W/2)/tan(HFOV/2)，cx/cy 居中，畸变 0），但相机创建路径带 5.1 焦距单位 bug 且与打印不同源——**两份均已修复**（创建改用 pinhole_k['focal_mm']/1000 落地，与打印 K 同源）。RouteManager 拷贝另有 `INTRINSICS` 标定表 + 创建时读表功能。**语义修正：仿真数据用 hfov 推导的 K 就是自洽且足够的内参**（虚拟相机无"标定"概念，camera_info 与渲染一致即可）；实物标定 fx/fy/cx/cy 只在真机数据/对齐真机视野时需要。`add_camera` 的 intrinsics 参数（fx/cx/cy→焦距/apertureOffset）供后续真机对齐用，符号待投影验证。
- 教训：standalone_server.py --demo 测试时脚本里的 `wait` 会等 demo 服务本身（run_duration=600s）导致超时，测完要 pkill（用 `[s]` 方括号模式防自杀，见 [[gripper-swap-task]]）。
