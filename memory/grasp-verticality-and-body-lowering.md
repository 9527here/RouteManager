# 远物抓取：降机身 + 接近轴必须铅垂（2026-10-14）

用户："只要方块离机器人稍微远一些，就不能够垂直抓下去，会有一个角度。
这种情况可以调节机身变矮一些，然后去抓。" —— 诊断正确，照做了。

## 改了三处（`robot_manager.py` 的 auto_pick 规划/执行）

1. **`body_offsets` 从 `(0.0,)` 改回 `(0.0, -0.06, -0.12, -0.18)`**。
   2026-10-13 曾把它关成 `(0.0,)`，理由是"降机身不生效"。真正的病根是下面第 2 条。

2. **`plan_tick` 里规划选中的机身升降量以前根本没被用上**（真 bug）：
   ```python
   ap["body_dz"] = float(info.get("body_dz", 0.0))   # ← 永远是 0
   ```
   `plan_grasp_steps` yield 的是 `(score, qs, info, dz)`，`dz` 在第 4 个返回值里；
   `info` 只由 `_plan_grasp_at` 填了 `infos`（**只有非生成器的 `plan_grasp`
   才往 info 里补 `body_dz`**）。所以规划按"机身降了 dz"解的 IK、实际机身没降，
   TCP 整体高 dz → 抓空。改成 `ap["body_dz"] = float(dz)`。

3. **`body` 相位改成等机身"真的"到位**（原来只等 `_motion is None` = 插值发完）：
   存下目标 `ap["body_tgt"]`，判据用**实测 `lift_joint` 位置**（±5mm），超时 4s。
   与 `pre` 相位那处是同一个坑。

顺带把 `accept_score` 从 45 压到 **20**：45 分意味着"位置 0mm + 朝下偏 5.6°"
也直接接受，那就不会再去试更低的机身。

## 实测效果

| | 近物 forward 0.44~0.58 | 远物 forward 0.56~0.70 |
|---|---|---|
| 规划选的机身 | +0.00m | **-0.18m** |
| 下降段接近轴偏离铅垂 | 中位 0.26° / 最大 0.51° | 中位 0.36° / 最大 0.57° |
| 下降段 TCP 横向漂移 | 1.0mm | 2.5mm |
| 结果 | 完成 | 完成 |

`auto_pick` 新增 `forward=[a,b]` 参数（默认 0.44/0.58），方便故意放远来测这条路径。

## 附：怎么量"接近轴是不是铅垂"

夹爪的接近轴 = `{side}_gripper_base_link` 世界变换的 **+Z 列**；
铅垂偏离角 = `arccos(|axis_z|)`。逐帧取 descent 段统计中位/最大。

相关 [[rm65-grasp-failure-root-cause]]。
